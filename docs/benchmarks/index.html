IHatePDF 2.0: rebuilt in Rust, measured

1.4.0 (Electron + TypeScript engines) compared with 2.0.0 (Tauri + Rust core, TypeScript engines kept as fallback).

The short version

  • The installer went from 123.8 MB (1.4.0, Electron) to 27.9 MB (2.0.0, Tauri).
  • Compress: 2.8x to 3.4x faster in the app on scans and photos, with equal or better image quality (SSIM) at every level, and about 5x less extra peak memory (+130 MB instead of +706 MB on a 10 MB scan).
  • PowerPoint to PDF was rewritten as a real DrawingML renderer: the page difference from PowerPoint's own PDF fell from 79.3 to 2.0 on decks built in PowerPoint, and from 26.8 to 8.2 on real lecture decks.
  • Every tool that moved to Rust was compared against the old TypeScript engine on the same inputs before it shipped; where Rust cannot do a job it hands it to the TypeScript engine, so 2.0 is never worse than 1.4.0 on a file.
  • Not faster everywhere: the text analysis is level with TypeScript (1.1 s vs 1.0 s), idle memory is the same (WebView2 draws the same page), and Protect, Unlock, Forms, PDF/A and the Compare word diff stay on TypeScript by design.

What these numbers do not say

  • Rust is not faster for every tool. The honest summary is: smaller installer, faster and lighter Compress, a much better PowerPoint to PDF, level on most others.
  • Protect, Unlock, Forms, PDF/A and the Compare word diff run on the TypeScript engines on purpose (security-critical or no measured problem).
  • Text that needs an embedded Unicode font in Edit PDF, and password-protected files, run on the TypeScript engine.
  • PowerPoint charts cover bar, column, stacked, line, area and pie only; EMF/WMF pictures, 3D, glow and WordArt effects are not drawn; SmartArt is untested; the Rust PowerPoint output has been opened in real PowerPoint but not in LibreOffice.
  • Share to phone: only Wi-Fi mode is in 2.0 (not yet tried on a real phone); the PC hotspot, Bluetooth and the local usage log from 1.4.0 are not in 2.0.
  • The installer is not code-signed, so Windows SmartScreen warns on first run.

How to reproduce

cd crates/ihp-core && cargo build --release
PY=py PYTHONIOENCODING=utf8 npx tsx scripts/test-editapply-rust.ts
PY=py PYTHONIOENCODING=utf8 npx tsx scripts/test-pptx-real.ts   (needs PowerPoint for the reference PDFs: scripts/make-ppt-decks.ps1)
E2E_CDP=http://127.0.0.1:9333 node scripts/e2e/all-tools.mjs     (against the installed app started with --remote-debugging-port=9333)

Measured on Windows 11 build 26200, Intel Core Ultra 9 185H, 31.4 GB RAM (one laptop), 2026-09-30 to 2026-11-19. Single machine, single user. Treat the numbers as indicative, not as a lab benchmark. Raw outputs are not committed (test-fixtures/ is gitignored); every script is in scripts/ and the run notes are in docs/testing/.
